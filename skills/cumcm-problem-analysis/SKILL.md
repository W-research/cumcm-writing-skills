# 国赛问题分析

把现实任务转化为有依据的建模路线，说明为什么这样建模、输入输出是什么、怎样求解和检验。算法名称和操作顺序服务于论证。

## 工作状态与权限

- **方案稿**：题目或路线未定时，写拟采用的方法、条件与检验计划；说明关键选型取决于什么数据。
- **论文回写**：根据实际模型、代码和结果解释已有路线，区分已实施的验证与建议补充项。
- **仅审查**：报告位置、论证缺口、数学矛盾和影响，保持源文件不变；局部替换措辞按请求提供。
- **改写/修改文件**：改写只交付获准范围的文字；明确要求修改文件才写回，保留其他章节和实际模型。

用户已选路线时沿该路线解释；实质技术问题在正文外说明，模型变更另按授权处理。局部材料不足时完成确定部分；缺少研究对象或各问任务时请求必要材料。

## 从题目到章节

### 1. 逐问整理论证依据

记录任务与子任务、输入输出、数学类型、难点、实际数据特征或待验证条件、主路线、求解检验与跨问接口，保留材料位置。底稿用于判断，正文不必逐字段列出。

按变量和目标结构判断数学本质。优化题关注决策变量、目标和约束；预测/分类题关注标签、可用特征和划分；机理题关注状态、机制与可控制量。题设信息、真实数据观察和条件方案分别使用准确语态。

### 2. 说明路线为何适合

存在会改变假设、结果含义或计算代价的合理替代时，解释主方案与其取舍。比较以题目条件为依据，可以是理论比较，不冒充未做的实验。固定路线、简单确定性计算或没有实质替代时，只解释采用依据与检查方式，不凑陪衬算法。

模型成立条件要讲清；公式推导、完整符号表和代码细节留到建模与求解。检查目标和约束共同决定的结构；LP、动态规划和守恒关系满足各自前提。有限/启发式搜索的解质量按可行性、基线和可得界表述；全局最优、因果、显著性等主张需相应证据。

### 3. 形成逐问叙事

一般按“任务与数学本质—难点及数据/变量特征—主路线与必要取舍—求解检验—必要衔接”组织，每问一至数段。沿用论文编号。约1页、复杂题1–2页只是参考，当前请求与模板优先，完整覆盖优先于凑页数。

回写稿对应实际工作，方案稿明确计划状态。保留解释选型所需的事实，结果表留后续章节。真正影响路线的缺口集中说明，不用虚构数值或模型优势填补。

### 4. 按需交付流程图

默认只给正文。明确要求图时，再展示模型、输入、输出、真实依赖和检验反馈；区分结果流、方法复用、共享数据的并行关系。未定路线标为方案图。按目标格式交付并验证呈现；Mermaid源码或可解析状态不是图片版面验证。

### 5. 对照实际材料

逐问核对覆盖、变量目标、选择理由、检验相关性与依赖接口。图在交付范围内时逐箭头检查。数据泄漏、评分冒充概率、任务被目标替换等矛盾优先于语言润色处理。

只交指定章节，缺口和建议放正文外；不自动扩展为其他章节或完整求解。章节与材料一致不等于模型已在现实中验证，按实际程度报告。

需要 Word/MathType 公式时，读取当前环境中可用的 `mathtype-texvc`；独立安装而缺少该技能时说明转换验证缺口，本节仍以路线论证为主。
