# 分析反例与复核

## 从流程流水账改成理由链

弱：“先处理数据，再用模糊评价；问题二用遗传算法，问题三用动态规划。”

缺失的不只是连接词，而是各问数学任务、特征依据、难点、选型比较和可检验性。不要把它机械扩成长句；先恢复论证底稿，再写正文。

改写时按这条顺序追问材料：题目到底要求输出什么？什么条件使它不能直接算出？模型利用了哪项信息或结构？存在实质替代时，为什么不优先采用？哪种检验能暴露这条路线的失败？

## 容易被“好写法”掩盖的技术问题

| 原表达 | 问题 | 修订原则 |
|---|---|---|
| 变量连续且约束线性，所以 LP；目标非凸 | 分类前提自相矛盾 | 同时检查目标与约束；据实际结构改写 |
| 遗传算法验证全局最优性 | 搜索结果不是最优性证明 | 报告可行性、基线、界或适用证明 |
| 指标多，所以采用模糊评价 | 数量不证明模糊语义 | 说明隶属度与等级为何有意义 |
| 熵权使评价完全客观 | 忽略指标、预处理与偏好的选择 | 限定其作用，检查权重依赖 |
| 三问自然依次承接 | 可能没有真实接口 | 区分结果传递、方法复用与并行 |
| 模型以未来变量解释当前预测 | 信息泄漏 | 按决策时点界定可用特征 |
| 用 R² 检验优化方案 | 指标与失败机制无关 | 改为约束复算及适用的解质量证据 |
| 方差最小就稳定在目标附近 | 可能稳定在错误水平 | 同时回应目标偏差与波动 |
| 成本、收益都是约束 | 混淆目标项与限制 | 按数学作用分类 |
| 有时间维度便用动态规划 | 未说明充分状态与转移 | 先检查状态表达及计算可行性 |

## 已有模型回写

把分析中的每个模型名、输入、目标、求解步骤、检验和跨问接口与实际正文比对。

- 现有模型用的是整数规划，不能为了写作“高级感”改成遗传算法。
- 实际没有比较实验，可以写结构比较，不写候选方法实验排名。
- 实际尚未检验，不能写“经检验表明”。正文外说明待补检验，或按用户要求写清拟检验内容。
- 题目与模型目标不一致时，说明差异；不修改题目来迁就模型。

## 交付前实质检查

| 维度 | 可接受证据 |
|---|---|
| 任务覆盖 | 每问及内部子任务均可回指原题 |
| 数学本质 | 变量、对象与任务支持所说类型 |
| 数据依据 | 已观察特征有材料来源，未观察特征标为条件 |
| 方案取舍 | 有实质选型时比较合理替代；固定路线或简单计算可只说明采用依据，不因缺少陪衬方案判为漏项 |
| 求解检验 | 方法与结构相容，检验能暴露真实失败 |
| 问题关系 | 每条依赖有具体传递对象；独立关系未被强串 |
| 图文一致（交付或审查范围含图时） | 节点、箭头、方案/完成状态与正文一致；不为检查此项自动生成图 |
| 写作边界 | 无公式推导、代码日志、虚构结果和无依据的最优性表述 |

这些是编辑检查项，不是比赛评分表，也不推导奖项概率。先修实质遗漏，再压缩重复句、模型百科说明和泛化意义陈述。
