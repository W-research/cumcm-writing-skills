# 从任务到模型的论证

## 用证据写选择理由

每问的工作底稿包含：任务、数学本质、输入与输出、难点、可验证特征、主方案、存在实质取舍时的替代方案、求解、检验、跨问关系。底稿用于组织论证，正文不必逐项列出。

把三个层次区分清楚：

- “题目给出不同时间的观测值”是题设信息。
- “序列存在明显季节性”需要真实检查支持。
- “若发现季节性，则采用相应时序模型”是有条件方案。

只有题面时可以分析潜在难点，不能装作已完成 EDA。回写时可依据实际材料写“数据表现为……”，但须能找到证据。

## 有实质选择时进行有效比较

比较的基本形态是：本题需要什么，主方案利用了哪项条件，替代方案在哪项条件上受限，采用什么检查来判断选择是否合理。

| 任务 | 主方案需要论证的关键点 | 可比较的合理路线 | 不能自动成立的理由 |
|---|---|---|---|
| 预测 | 预测时点可用信息、样本量、时间依赖、非线性与可解释性 | 简单趋势/持续值基线、回归、树模型、时序模型 | 数据多就该用深度学习；相关就有因果 |
| 分类 | 标签含义、类别比例、误判成本、部署对象 | 逻辑回归、树模型、规则基线 | 无标签也能报告监督分类精度 |
| 评价 | 指标方向、量纲、冗余、偏好与等级语义 | 加权评分、TOPSIS、模糊评价，必要时 AHP 作偏好赋权 | 指标多就模糊；熵权消除了全部主观性 |
| 优化 | 决策变量的离散/连续性、目标与约束结构、可行性 | 解析策略、LP/MILP、非线性求解、启发式 | 变量连续就 LP；启发式收敛即全局最优 |
| 机理/反演 | 守恒关系、状态、参数可识别性、观测信息 | 解析近似、数值动力学、经验拟合 | 模型越复杂越真实；只有方程就已验证 |
| 聚类 | 是否需要发现群组、距离语义、尺度、类别未知 | K-means、层次/密度聚类，必要时有监督分类 | 分类与聚类可以只按名称互换 |
| 动态决策 | 状态是否含决策所需历史、动作、转移与时域 | 动态规划、滚动优化、静态情景基线 | 有时间变量就满足贝尔曼递推条件 |

这张表是判断提示，不是模型推荐排行榜。一次具体任务只讨论真正相关的主方案；存在会改变假设、结果含义或计算代价的合理替代时才比较，不设每问必有比较的次数要求。

## 三种特殊情况

### 用户已有模型

读实际建模部分，解释现有方法如何对应任务。没有做过候选模型实验，可以写结构层面的取舍，不能编出某模型精度提高了多少。若用户只要语言润色而方案明显有问题，保留其已授权范围，在正文外指出技术冲突；不要把矛盾包装成肯定结论。

### 题目规定模型或计算很简单

不假装仍可自由选型。若只有题设规定的确定性计算，说明输入、关系成立条件和核对方式即可，不必比较。解析与数值实现、完整与简化表示、精确与近似求解只有确实改变精度、代价或适用范围时才有比较价值；不能机械添加一种明显不合适的复杂方法充当陪衬。完整示例见 [固定路线回写](worked-example.md)。

### 缺少足够信息定具体方法

确定主路线到已有证据支持的层级，例如“可解释风险预测 + 预算约束下的额度分配”，并说明模型细化依赖什么数据。将不确定性放在具体条件上，避免每句含糊，也不要强称选型已验证。

## 把操作变成数学解释

弱：“先清洗数据，再训练模型，最后检验。”

较好：“预测任务需要区分随时间变化的规律与异常观测。拟先核对观测时间和缺失区间，再依据可用样本建立趋势基线；若残差仍有稳定的时间依赖，则引入能够表达该依赖的模型。性能在未参与拟合的后续时段比较，以检验对未来情景的预测能力。”

增加的是理由、条件和可检验标准，而不是工具名称。没有数据时这只是方案说明，不是已完成的实验。

## 优化与动态决策的数学底线

- LP 的目标函数以及等式/不等式约束均为线性或仿射结构；有整数选取变量时需辨认为相应整数规划。只检查约束不够。[SciPy 线性规划定义](https://docs.scipy.org/doc/scipy/reference/generated/scipy.optimize.linprog.html)
- 非凸优化可以用多初值、不同算法和可行性检查提供求解证据；全局最优结论需要适用的证明、界或可认证求解信息，随机搜索本身不足。[MathWorks 遗传算法说明](https://www.mathworks.com/help/gads/what-is-the-genetic-algorithm.html)
- 引入动态规划前说明状态、动作、转移、阶段成本/收益及边界；若历史影响不能由状态概括，需要扩充状态或比较其他方法，而非直接写“由最优性原理求解”。

正文只保留与当前题目有关的一两句，不把这些边界全文塞入每篇论文。
