# 摘要写作与精简

## 先提取，再压缩

摘要通常在模型、求解和结果已稳定后完成。材料尚未齐全也可先整理草稿，但不能提前写出尚未取得的结论。先按各问提取交付任务、方法、结果和条件，再寻找全文共同主线，最后压缩文字。

优先保证每问都回答了题目。信息密度不是算法和数字的数量，而是读者能否把方法与答案对应起来。

## 开头段

信息优先级：本文完成的工作 > 必要背景 > 有依据的意义。两到三句通常足够；简单任务也可一句说明，不为凑句数增加背景。

可按需套用并改写：

> 本文针对〔对象〕的〔核心问题〕，基于〔关键机制/数据〕建立〔主模型〕，研究〔主要任务及输出〕。

若背景有助于理解物理机制或决策冲突，可在此前补一句。不要用行业发展史、“随着科技不断发展”等背景代替本论文工作，也不必在开头列全所有算法与软件。

## 主体段

提出问题有三种方式：直接概括求解任务；把任务融入模型描述；指出数学问题类型。通常第二种最紧凑，复杂交付可用第一种，第三种仅在分类能解释建模思路时使用。

| 题型 | 方法至少交代的关系 | 优先保留的结果 |
| --- | --- | --- |
| 机理/数值计算 | 物理机制、状态变量或守恒关系如何导向模型；关键求解方法 | 题目要求的物理量、条件、必要精度或误差 |
| 规划优化 | 目标、决策变量、关键约束与模型关系 | 选定决策、目标值或约束边界，及适用情景 |
| 预测 | 输入与预测对象、时间范围、模型作用 | 预测值或趋势；已有验证误差或区间 |
| 评价/分类 | 指标如何构造、模型如何评价对象 | 排序、分组、关键影响因素或诊断结论 |
| 方案/策略 | 触发条件、行动与优化或评价准则 | 可执行的规则和有依据的效果；不只说已提出建议 |

可用表达骨架：

> 针对问题〔序号〕，依据〔题目机制/数据关系〕，以〔目标〕、〔变量或关键约束〕建立〔模型〕，采用〔必要的求解方法〕得到〔核心结果及条件〕。

这不是要求每段都塞满所有槽位。预测问题不应被强写成优化问题；结论的意义已明显时，不必再补一句“为……提供参考”。

多问共享模型时，可写“在问题一的模型中加入〔新增机制/约束〕”，随后交代本问结果；避免复制建模过程。新增假设显著限制结论时保留其边界。

## 事实范围与正文外说明

把范围落到对象和条件上，例如“在2021年的留出数据上评估公交客流预测误差”“在题设给定的三种线路方案中比较出行时间”。这些条件帮助理解结果，应放在正文中；具体对象、指标和数值采用当前研究记录。

尚待开展的验证、材料缺项，以及依现有证据还无法回答的后续事项，都属于工作状态，例如“待补不同季节的客流观测”。确有提示必要时，在关键词后另列“正文外说明”，不要变成每问段末的转折或摘要免责结尾。正文保留已完成研究的答案，缺少答案的子任务另行提醒作者补充；缺少研究材料不等于已经证明问题无解。没有相应统计检验时，用实际差值代替“显著提升”，即可让主张与证据相符。

直接回答题目的负面结果仍需留在摘要，例如“给定运力下无法满足高峰客流需求”；它不是待补验证说明。正文外的说明不能代替必答结果，也不能用免责声明补救正文里没有依据的泛化、因果或最优性主张。

## 数字与长方案

- 区分决策变量值、目标函数值和验证指标，不能只报一串数字让读者猜作用。
- 每个数字保留必要单位、对象和情景。列多个情景时，确保条件与结果一一对应。
- 按证据精度表达，避免无依据的长小数；敏感阈值或必要容差也不能随意舍入。
- 大规模排序、逐企业贷款方案、长控制时序等可保留总体结论与关键案例，并准确指向完整结果位置。
- 页长与覆盖冲突时，优先压缩推导和重复语句，再压缩次要结果；不能用固定数字预算删掉必答小问。

## 结尾与空话修复

结尾段可省，但不因追求精简自动删除。已有验证结果可以放在相关问题段末尾，无需再重述一遍。结尾若保留，应增添综合发现或具体适用条件；未实施的验证放正文外，不以空泛自我限制收尾。需要用户定向时，参考 [方向选择](decision-points.md)，展示可成立的结尾短稿或融入主体的方案；已明确的选择直接执行。

| 空泛表达 | 有证据时的替换方向 | 没有证据时 |
| --- | --- | --- |
| 模型结果较优 | 说明同一条件下相对哪种基线、哪个指标变化多少 | 删除评价，只陈述已知结果 |
| 使用了较好的方法 | 说明方法解决了什么具体机制或数据困难 | 写清方法作用，不评价优越性 |
| 模型灵敏性较好 | 参数在什么范围变化、哪个输出如何变化 | 不写稳健性结论 |
| 有显著提升 | 提供相应比较；涉及统计显著性时给出已有检验依据 | 写已证实的差异，不暗示完成检验 |
| 最后分析了优缺点 | 写一项实际发现的优势或限制 | 省略结尾 |
| 具有广泛推广价值 | 说明模型可适用的条件；未验证时写成可能扩展方向 | 不作为已证实贡献 |

## 摘要重点加粗的选择与示例

作者整理的信贷和“穿越沙漠”截图，用粗体强调了模型名称、递推关系/数学期望等关键思路、求解或验证方法，以及主要结果。应提炼其便于扫读的做法，不逐项复制截图里的全部粗体。截图还强调了一些软件名，这些通常不如模型和答案重要。

| 内容类别 | 截图中的例子 | 选择依据与边界 |
| --- | --- | --- |
| 主模型 | 信贷风险评估模型、非线性多目标规划模型、单目标最优化模型、决策模型 | 优先突出本问实际使用的核心模型完整名称；避免仅加粗“模型”二字 |
| 关键思路/目标 | 正则项、集成学习思想、递推关系式、数学期望、收益最大/风险最小 | 能说明模型构造、任务变化或改进所在时选取；无需每个环节都强调 |
| 求解与验证 | 贪心法和回溯法、博弈论、蒙特卡洛方法 | 承担关键作用时选取；模型与算法不必全都加粗，博弈论等理论也不能误写成算法 |
| 数值答案 | 96.75%、199.635 万元、10470/12730 元、10065 元 | 加上必要指标名、对象和单位；这些只是样例值，不可直接用于新论文 |
| 策略与诊断 | 贷款方案、路线决策、影响因素下的调整规则 | 优先加粗实际方案或具体结论；“最佳策略”这样的标签不能代替策略内容 |
| 软件与一般操作 | MATLAB、C++、Lingo、Python 爬虫 | 截图虽有强调，但通常保留正常字重，不与数学贡献争夺注意力 |

### 加粗范围应承载完整信息

以下均为基于教学材料的改写示例，不代表已核验其模型与结果。

> 建立**信贷风险评估模型**，样例报告的**预测准确率为 96.75%**。

这比把“模型”和“96.75”分别加粗更清楚：模型名完整，指标与百分号没有脱离数值。比较两个方法时，还需完整保留基线、同一评价条件和百分点/相对百分比口径，不必把所有比较数字都加粗。

> 针对问题一的稳压任务，根据燃油压力与密度的关系建立**压力变化微分模型**，将其离散化后，以稳态压力偏差平方和最小为目标搜索单向阀开启时长，得到**开启时长为 0.288 ms** 的方案。

这里优先强调主模型与主要答案。若本段真正需要突出目标函数的设计，可再强调目标短语；不必同时把“离散化”“搜索”及全部过程词加粗。这仍只是稳压子任务的示例，不能覆盖原题另有的压力调整任务。

开放策略题可使用“在〔已证实的条件〕下，采用**〔明确的行动或选择规则〕**”这样的结构。加粗实际方案，保留控制其成立的条件；无数值也可形成清楚的结果重点。

### 最后做两次阅读

- **只扫粗体**：能否找到本问的主要模型、思路或答案；是否尽是算法却没有结果；相邻粗体是否连成大块。
- **通读全文**：加粗范围是否完整、条件是否遗漏、重复术语是否过度强调、是否仍能自然阅读。若过密，先取消一般过程、重复方法和次要数字的粗体，不删必答内容。

## 交付前一分钟检查

读者只看首页，应能回答：研究对象是什么、各问如何解决、各问得到什么、主要结果适用于什么情形。再核对标题覆盖面、关键词对应、数值一致性、粗体重点和页长。

正文未提供时，能检查结构与文字，不能声称已核对模型结果；未渲染时，能估计篇幅，不能声称首页已排成一页。
